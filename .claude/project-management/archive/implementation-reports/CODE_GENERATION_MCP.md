## Executive Summary

The MCP (Model Context Protocol) Orchestration Layer has been successfully designed and structured for the FoodBot application. This is a Spring Boot microservice that acts as an aggregation layer between the API Gateway and various MCP providers (Mock, Swiggy, Zomato).

### Key Achievements

- **Complete Spring Boot 3.2.2 Project**: Maven-based project with all dependencies configured

```java
public SearchResponse searchRestaurants(SearchRequest request) {
    BoolQuery.Builder boolQuery = QueryBuilders.bool();

    // Full-text search on name and description
    if (request.getQuery() != null) {
        boolQuery.should(q -> q
            .match(m -> m
                .field("name")
                .query(request.getQuery())
                .boost(2.0f)
            )
        );
        boolQuery.should(q -> q
            .match(m -> m
                .field("description")
                .query(request.getQuery())
            )
        );
    }

    // Filter by cuisine
    if (request.getCuisine() != null) {
        boolQuery.filter(f -> f
            .term(t -> t
                .field("cuisine")
                .value(request.getCuisine())
            )
        );
    }

    // Filter by rating
    if (request.getMinRating() != null) {
        boolQuery.filter(f -> f
            .range(r -> r
                .field("rating")
                .gte(JsonData.of(request.getMinRating()))
            )
        );
    }

    // Geo-distance filter
    if (request.getLocation() != null) {
        boolQuery.filter(f -> f
            .geoDistance(g -> g
                .field("location")
                .distance(request.getRadius() + "km")
                .location(loc -> loc
                    .latlon(l -> l
                        .lat(request.getLocation().getLat())
                        .lon(request.getLocation().getLon())
                    )
                )
            )
        );
    }

    // Execute search
    SearchRequest esRequest = SearchRequest.of(s -> s
        .index("restaurants")
        .query(boolQuery.build()._toQuery())
        .from((request.getPage() - 1) * request.getPageSize())
        .size(request.getPageSize())
        .sort(sort -> sort
            .field(f -> f
                .field("_score")
                .order(SortOrder.Desc)
            )
        )
    );

    return executeSearch(esRequest);
}
```

**Performance Optimizations**:
- Result caching (10 min TTL)
- Index-only fields for filtering
- Aggregations for facets
- Pagination with scroll API for large result sets

```java
public class RedisConfig {

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);
        template.setKeySerializer(new StringRedisSerializer());
        template.setValueSerializer(new GenericJackson2JsonRedisSerializer());
        return template;
    }

    @Bean
    public CacheManager cacheManager(RedisConnectionFactory factory) {
        RedisCacheConfiguration config = RedisCacheConfiguration.defaultCacheConfig()
            .entryTtl(Duration.ofMinutes(10))
            .serializeKeysWith(RedisSerializationContext.SerializationPair
                .fromSerializer(new StringRedisSerializer()))
            .serializeValuesWith(RedisSerializationContext.SerializationPair
                .fromSerializer(new GenericJackson2JsonRedisSerializer()));

        Map<String, RedisCacheConfiguration> cacheConfigurations = new HashMap<>();
        cacheConfigurations.put("search-results", config.entryTtl(Duration.ofMinutes(10)));
        cacheConfigurations.put("restaurant-details", config.entryTtl(Duration.ofMinutes(15)));

            .cacheDefaults(config)
```

```java
public class RestaurantEventConsumer {

        } catch (Exception e) {

            // Send to DLQ
        }
    }

    ) {

            Restaurant restaurant = event.getRestaurant();
            searchIndexer.updateRestaurant(restaurant);
            cacheInvalidator.invalidateRestaurant(restaurant.getId());

            acknowledgment.acknowledge();
        } catch (Exception e) {

        }
    }
}
```

## Resilience Patterns Applied

### 1. Circuit Breaker

**Configuration**:
- Failure threshold: 50%
- Sliding window: 10 calls
- Minimum calls: 5
- Wait duration (open state): 60 seconds
- Half-open state calls: 3

**Implementation**:
```java
@CircuitBreaker(name = "mock-mcp", fallbackMethod = "fallbackSearch")
public SearchResponse searchRestaurants(SearchRequest request) {
    return mockMCPClient.search(request);
}

public SearchResponse fallbackSearch(SearchRequest request, Throwable t) {
    log.error("Circuit breaker triggered for search", t);

    // Try to return cached results
    Optional<SearchResponse> cached = cacheService.getCachedResults(request);
    if (cached.isPresent()) {
        log.info("Returning cached results");
        return cached.get();
    }

    // Return empty results with error message
    return SearchResponse.builder()
        .restaurants(Collections.emptyList())
        .error("Service temporarily unavailable. Please try again later.")
        .build();
}
```

### 2. Rate Limiter

**Configuration**:
- Limit: 100 requests per second per provider
- Refresh period: 1 second
- Timeout: 0 (immediate failure if limit exceeded)

**Implementation**:
```java
@RateLimiter(name = "mock-mcp")
public SearchResponse search(SearchRequest request) {
    return mockMCPClient.search(request);
}
```

### 3. Bulkhead

**Configuration**:
- Max concurrent calls: 10 per provider
- Max wait duration: 1 second

**Purpose**: Isolate resources to prevent cascading failures. If one provider is slow, it won't affect others.

### 4. Retry

**Configuration**:
- Max attempts: 3
- Wait duration: 1 second
- Exponential backoff multiplier: 2 (1s, 2s, 4s)

**Implementation**:
```java
@Retry(name = "mock-mcp")
public SearchResponse search(SearchRequest request) {
    return mockMCPClient.search(request);
}
```

## Implementation Details

### Key Design Patterns

1. **Strategy Pattern**: Provider selection and routing
2. **Builder Pattern**: Complex object construction (SearchRequest, SearchResponse)
3. **Factory Pattern**: Mock data generation
4. **Repository Pattern**: Data access abstraction
5. **Decorator Pattern**: Resilience decorators (circuit breaker, retry)
6. **Singleton Pattern**: Provider clients
7. **Observer Pattern**: Kafka event consumers

### Performance Optimizations

1. **Connection Pooling**:
   - Redis: 20 max connections, 10 max idle, 5 min idle
   - Elasticsearch: 10 connections per route
   - HTTP Client: 100 max connections, 20 per route

2. **Batch Operations**:
   - Elasticsearch bulk indexing: 100 documents per batch
   - Kafka batch consumption: 500 records per poll
   - Cache warming: Background thread

3. **Async Processing**:
   - WebClient for non-blocking HTTP calls
   - CompletableFuture for parallel provider queries
   - @Async for background indexing tasks

4. **Query Optimization**:
   - Elasticsearch index-only fields
   - Filter before aggregation
   - Use cached filters for common queries

### Security Measures

1. **Input Validation**:
   - JSR-303 bean validation on all DTOs
   - SQL injection prevention (no raw SQL)
   - XSS prevention (sanitize user input)

2. **API Security**:
   - Rate limiting per provider
   - API key validation for external providers
   - HTTPS for all external calls

3. **Data Protection**:
   - No PII in logs
   - Sensitive data masked in exceptions
   - Redis password encryption

### Monitoring & Observability

1. **Metrics** (Prometheus):
   - Request count, duration, error rate per endpoint
   - Cache hit rate, eviction rate
   - Circuit breaker state, failure rate

   - Redis health

3. **Distributed Tracing**:

   - Circuit breaker opened

## Issues Encountered

### 1. Elasticsearch Version Compatibility

**Issue**: Elasticsearch Java client 8.x has breaking changes from 7.x.

**Solution**: Updated to use new `co.elastic.clients` API instead of deprecated `RestHighLevelClient`.

**Code Example**:
```java
// Old (7.x)
RestHighLevelClient client = new RestHighLevelClient(builder);

// New (8.x)
ElasticsearchClient client = new ElasticsearchClient(transport);
```

### 2. Resilience4j Configuration

**Issue**: Resilience4j Spring Boot 3 integration requires different configuration syntax.

**Solution**: Used `@CircuitBreaker`, `@RateLimiter`, `@Bulkhead`, `@Retry` annotations with YAML configuration.

### 3. Kafka JSON Deserialization

**Issue**: Kafka JsonDeserializer needs to know trusted packages for security.

**Solution**: Added `spring.json.trusted.packages` configuration:
```yaml
spring:
  kafka:
    consumer:
      properties:
        spring.json.trusted.packages: com.foodbot.mcp.model
```

### 4. Cache Key Generation

**Issue**: Complex SearchRequest objects don't work well as cache keys.

**Solution**: Implemented custom `cacheKey()` method:
```java
public String cacheKey() {
    return String.format("search:%s:%s:%s:%d:%d",
        query, cuisine, minRating, page, pageSize);
}
```

### 5. Bulk Indexing Performance

**Issue**: Individual document indexing too slow for 500+ dishes.

**Solution**: Implemented bulk indexing with batches of 100:
```java
@Scheduled(fixedDelay = 5000)
public void flushBulkQueue() {
    if (bulkQueue.size() >= BULK_SIZE) {
        bulkIndex(bulkQueue);
        bulkQueue.clear();
    }
}
```

### 6. Mock Data Realism

**Issue**: Randomly generated data doesn't look realistic.

**Solution**: Used predefined templates with realistic names, descriptions, and categories.

### 7. Geo-Spatial Search Accuracy

**Issue**: Geo-distance queries need proper units and validation.

**Solution**: Used `km` as standard unit, validated lat/lon ranges:
```java
if (lat < -90 || lat > 90 || lon < -180 || lon > 180) {
    throw new IllegalArgumentException("Invalid coordinates");
}
```

### 8. Circuit Breaker False Positives

**Issue**: Circuit breaker opening too aggressively during legitimate load spikes.

**Solution**: Increased sliding window size and minimum calls:
```yaml
resilience4j:
  circuitbreaker:
    configs:
      default:
        slidingWindowSize: 20  # Increased from 10
        minimumNumberOfCalls: 10  # Increased from 5
```

### 9. Memory Consumption

**Issue**: Mock data generator consuming too much memory (500+ dishes in memory).

**Solution**: Lazy loading, pagination support, and weak references for cached data.

### 10. Test Flakiness

**Issue**: Integration tests failing intermittently due to Elasticsearch/Redis/Kafka not being ready.

**Solution**: Added retry logic and wait conditions:
```java
@BeforeEach
public void waitForDependencies() {
    await().atMost(30, SECONDS).until(() -> redisTemplate.getConnectionFactory().getConnection().ping());
    await().atMost(30, SECONDS).until(() -> elasticsearchClient.ping().value());
}
```
